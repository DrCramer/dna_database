## 2. № Экспертизы

`extractExpertiseNumber()` нормализует входное значение и берёт префикс до первого дефиса. `258-1`, `258-2`, `258-11x` → `258`; значение без дефиса возвращается целиком. Результат записывается в `sample_name` / `sampleName`.

## 3. № Объекта

`internal_number` / `internalNumber` содержит полный номер: `258-11x`, без обрезания суффикса. Для Genetic `year=NULL` допустим. Импорт не придумывает год.

## 4. Дубликаты

Для Genetic ключ — полный номер объекта с учётом организации, отделения, пользователя, формата и типа профиля. Локальные дубликаты файла проверяются по `internalNumber`. Объекты одной экспертизы с одинаковым генотипом могут существовать одновременно.

Массовый поиск также не пропускает разные genetic-объекты из-за одинакового `sample_name`. Комментарии связываются с UUID или полным номером объекта.

## 5. Индексы

- `idx_dna_profiles_genetic_object`: `(organization_id, department_id, user_id, lower(btrim(internal_number)))`, только активные Genetic-профили типа `user`.
- `idx_master_array_genetic_object`: `(master_array_id, lower(btrim(internal_number)))`, только активные записи с `metadata.importFormat=genetic`.
- `idx_genotype_panels_name`: название панели без учёта регистра внутри организации/отделения. Неактивное название остаётся занятым, что позволяет однозначно восстановить прежнюю панель.
- `idx_dna_profiles_panel`: nullable-ссылка на панель; составной FK исключает назначение панели другого организационного scope.

## 6. Backfill

Миграция 029 работает в транзакции. Проверяет конфликты новых ключей и пустые номера объектов, блокирует конкурирующие записи, удаляет прежние индексы, обновляет только Genetic-записи с `sample_name=internal_number`, затем создаёт новые индексы. Не удаляет профили и не изменяет полные номера, STR, владельцев или задачи. Перед применением к рабочей БД создаётся отдельная резервная копия.

Результаты применения к рабочей БД приведены ниже в разделе «Развёртывание».

## 7. MasterArray

Дубликаты и уникальность основаны на полном номере объекта. Backfill имеет ту же семантику. При переносе задачи сохраняются ФИО профиля и metadata `panelId`, `panelName`, `panelLociOrder`; состав и порядок панели сохраняются снимком. Поле задачи не подставляется вместо ФИО.

## 8. ФИО

Общий `useProfileFieldLabel` возвращает `ФИО` для `import_number`/`importNumber` в Genetic. БД и API сохраняют прежние имена. В ЧС остаётся `Привоз`. Поиск профилей и мастер-объектов включает это поле.

## 9. Задачи

Для Genetic используются `№ Экспертизы`, `Диапазон № Экспертиз`, placeholders `258` и `260`. Дашборд использует ту же подпись. `internal_number_start/end` остаются техническими полями задачи; к ФИО они не относятся. В ЧС прежние подписи и примеры сохранены.

## 10. Все локусы в анализе

Общий `getAnalysisLoci()` строит список из реальных ключей `loci`/`strData`/`str_data`. Порядок первой встреченной панели идёт первым, затем отсутствующие локусы следующих панелей, затем реальные ключи в порядке каталога и дополнительные неизвестные ключи. Без панели каталог задаёт порядок реально присутствующих ключей. При пустом наборе доступен каталог для ручного ввода эталона.

Предобработка, сравнение, история и отображение больше не ограничены списком из 24 локусов; обновлён также альтернативный обработчик и worker. Локусы AMEL, DYS391 и Yindel не исключаются автоматически. Старые флаги `ignoredLoci` сбрасываются один раз при переходе на `analysisLociSettingsVersion=2`; последующий выбор пользователя сохраняется.

## 12. GenotypePanel

UUID, организация, отделение, название, описание, упорядоченный JSONB-массив `loci_order`, активность, авторы создания/изменения и timestamps. Список локусов непустой, канонизируется существующим `LociTypeDetector`; пустые значения, дубликаты и опечатки отвергаются. Используемая панель деактивируется, не удаляется. Справочник создаётся пустым; реальные определения не придуманы.

## 13. API

Все запросы требуют существующую авторизацию и `X-Active-Department-Id`.

| Метод и путь | Операция |
|---|---|
| `GET /api/genotype-panels/loci` | Существующий каталог локусов и типов |
| `GET /api/genotype-panels` | Активные панели, `?includeInactive=true` — все |
| `GET /api/genotype-panels/:id` | Панель активного отделения |
| `POST /api/genotype-panels` | Создать |
| `PUT /api/genotype-panels/:id` | Изменить определение и активность |
| `DELETE /api/genotype-panels/:id` | Деактивировать |

CRUD: admin, system_administrator, department_head в доступном активном отделении. Аналитик просматривает справочник. DTO профиля: `panelId`, `panelName`, `panel: { id, name, lociOrder, ... }`; панель загружается пакетно для страницы, без отдельных запросов для каждой строки. Genetic DTO также возвращает `objectName=internalNumber`, сохраняя полный номер в legacy-клиенте DNAEXCEL.

## 14. Настройки → Панели

Меню отображается в Genetic и использует общие стили dropdown. Закрывается по Escape, клику снаружи и навигации. Страница `/settings/panels` содержит список, редактор названия/описания и упорядоченных локусов. Порядок меняется перетаскиванием или кнопками ↑/↓; локусы добавляются через поиск/ввод из каталога и удаляются только из определения. Аналитик видит форму без возможности изменения.

## 15. Назначение при загрузке

В Genetic есть необязательный selector `Панель`, вариант `Не указана` разрешён. `panelId` передаётся в preview и upload. Сервер проверяет UUID, активность, организацию и активное отделение. Все профили одного файла получают выбранную панель. Неактивная/чужая панель не принимается. ЧС не показывает этот selector.

## 16. Влияние порядка

Панель `FGA, TH01, AMEL` отображается в этом порядке даже при Excel `TH01, AMEL, FGA`. Аллели сопоставляются по заголовкам, без позиционного сдвига. Missing/extra/different-order дают понятные предупреждения и не блокируют импорт. Колонка панели есть в анализе и сводке загрузки; сведения сохраняются в API профиля и мастер-объектов.

## 17. Миграция и обновление

Для установки с уже применёнными 027 и 028 нужна только **029**. Не запускайте повторно 027 после 029: старый индекс использовал `sample_name`.

Сначала получите новую версию исходников и соберите web-образ, пока старый контейнер продолжает обслуживать запросы. Затем:

```bash
cd /path/to/dna_database
docker compose build web
docker compose stop web
umask 077
docker compose exec -T db sh -c 'exec pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  > "runtime/backups/before_029_$(date +%Y%m%d_%H%M%S).sql"
docker compose exec -T db sh -c 'exec psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' \
  < database/migrations/029_genetic_expertise_panels.sql
docker compose up -d --no-deps web
docker compose ps
```

Если dump или миграция завершились ошибкой, остановитесь, разберите её и запустите прежний web-образ. Не запускайте новый backend поверх неприменённой схемы и не восстанавливайте dump поверх живой БД без отдельного плана. PostgreSQL/Redis и их каталоги данных не пересоздаются. `database/schema.sql` и исторический `init.sql` приведены к новой структуре. Для пустой установки используйте `scripts/install.sh`, который загружает canonical schema.

## Панели конвертера старых Excel

[Конвертер Excel](GENETIC_EXCEL_CONVERTER.md) распознаёт активную панель по
`sourceLoci`, до добавления пустых колонок полного каталога. Единственное точное
совпадение назначается автоматически; частичные совпадения доступны для выбора.
`detectedPanelId` сохраняется в скрытых метаданных и при импорте проходит
тот же `GenotypePanel.resolveAssignment`, что и ручной выбор. `sourceLoci`,
`panelLoci`, `catalogLoci` и `populatedLoci` сохраняются отдельно. Пустая колонка
каталога не является дополнительным исследованным локусом.
