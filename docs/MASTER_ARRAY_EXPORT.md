# Административный экспорт мастер-массива

## Использование

Откройте **Система → Экспорт мастер-массива**. Выберите организацию, отделение и активный массив из разрешённых вариантов. По умолчанию выбран весь активный набор; фильтры позволяют задать диапазон лет и подстроку номера объекта/экспертизы (в ЧС — объекта/присвоенного номера).

Нажмите **Проверить выгрузку**. Предпросмотр возвращает реальные количества, до десяти номеров без генотипов и причины проблемных записей. Кнопка скачивания становится доступна после проверки. Смена массива, отделения, фильтров или настроек очищает результат проверки.

Полная выгрузка запрещена при наличии непригодных записей. Можно скачать CSV со всеми исключениями, включить **Выгрузить только пригодные** и отдельно подтвердить исключение указанного количества строк. Такой файл имеет суффикс `только-пригодные`. Если данные меняются после проверки, сервер требует новый предпросмотр.

## Доступ

- На backend используются `authenticate` и существующий `authorize(['admin', 'system_administrator'])`; остальные роли получают 403 даже при прямом запросе.
- Область ограничена `User.getAccessibleDepartments()` и действующей политикой организации. `admin` не получает чужую организацию даже при ошибочной межорганизационной membership. `system_administrator` видит только явно доступные ему отделения, включая разрешённые межорганизационные membership; произвольного глобального перечисления массивов нет.
- Каждый экспорт повторно проверяет связь массива с отделением/организацией и их активность. Организация и отделение из тела запроса не принимаются. Существующие чтение, поиск и маршруты `accessible` не расширяются.
- Отсутствующая/недействующая сессия: 401; чужой массив: 403; отсутствующий массив: 404; неактивный источник или непригодная выгрузка: 409. Если первичное отделение/организация неактивны, действующий `authenticate` может инвалидировать сессию раньше проверки экспорта.

## Схемы и сохранность

Первый и единственный лист — **Импорт**, первая строка — заголовки. Конвертер и мастер-экспорт используют общий `src/utils/importWorkbook.js`.

| Формат | Колонки до локусов | Источник полей |
|---|---|---|
| Генетические экспертизы | Объект, Год | `internal_number` (полный номер), `year` |
| ЧС | № присвоенный в в/ч № 522 ЦПООП Северо-Кавказского военного округа, г. Ростов-на-Дону; Привоз; Год; Sample Name | `sample_name`; `import_number`; `year`; `internal_number` |

Mapping ЧС проверен по `ExcelService.extractProfileFromRow → DNAProfile → TaskService → MasterArray.addProfilesBatch`. При утверждении старых задач ЧС `TaskService` записывает в `import_number` поле `task.internal_number_start`; экспорт возвращает именно хранящееся значение. Первоначальное значение привоза, если оно было заменено при переносе, экспорт не восстанавливает и не угадывает. Отсутствующий/нечисловой привоз, неизвестный год и сгенерированный/неполный присвоенный номер требуют проверки вне экспорта.

Локусы сопоставляются канонически; объединяются все реально присутствующие локусы разных панелей. Порядок учитывает сохранённый `metadata.panelLociOrder`, затем общий каталог; половые локусы помещаются в конец. Можно явно включить весь каталог. Полностью пустые столбцы по умолчанию скрываются, значения не удаляются, служебные колонки всегда видимы.

Порядок аллелей, гомозиготы, одиночные вызовы, микроварианты, `?`, `*`, `F`, SRY и многокомпонентные генотипы сохраняются. Неизвестные локусы, конфликтующие алиасы, ошибочные аллели или значения, которые изменил бы штатный импорт, блокируют соответствующую запись. Пара «полный номер + год» проверяется без автоматического удаления дублей; все конфликтующие активные записи отмечаются проблемными.

Ячейки данных имеют строковый тип и формат `@`, без формул. UUID, имена людей, статусы, creator ID и панели не добавляются в импортные колонки. XLSX содержит только профили, без диагностического листа. Custom property `DNAProfileSourceFormat=MASTER_ARRAY_EXPORT` сообщает штатному парсеру о сохранении количества аллелей; это не обход валидации. Для legacy ЧС также исправлено чтение разрешённого граничного года 2100.

## API

Все запросы требуют `Authorization: Bearer …` и действующего `X-Active-Department-Id`. Выбранный массив может относиться к другому разрешённому отделению; его формат сервер определяет по реальной связи в БД.

```http
GET  /api/master-arrays/export/options
POST /api/master-arrays/:masterArrayId/export/preview
POST /api/master-arrays/:masterArrayId/export/xlsx
```

Пример тела проверки:

```json
{
  "filters": { "yearFrom": 2025, "yearTo": 2026, "objectQuery": "258" },
  "options": { "hideEmptyLoci": true, "includeCatalogLoci": false }
}
```

Неизвестные поля, некорректные типы и `includeInactive: true` отклоняются. Годы — числа 1900–2100. `objectQuery` ищется буквально, `%` и `_` не становятся wildcard. Для всех активных записей используйте `filters: {}`.

Предпросмотр: `totalMatched`, `exportable`, `needsReview`, полный `reasons` без STR-данных, `lociCount`, `totalExportRows`, `examples`, `fingerprint`, `importFormat`, `masterArray`.

При скачивании передайте те же фильтры и настройки, добавив `options.previewFingerprint` из ответа. Сервер заново выполняет выборку и preflight; числа и генотипы из браузера не принимает. Для частичной выгрузки дополнительно нужны `exportValidOnly: true`, `confirmValidOnly: true` и актуальный fingerprint. Для полной выгрузки API допускает запрос без предварительного fingerprint, но всегда выполняет собственную проверку.

## Объём и аудит

Данные читаются через keyset по UUID, порциями по 500 строк, внутри `REPEATABLE READ READ ONLY`. Все запросы привязаны к массиву, отделению и организации. Пагинация пользовательских таблиц не участвует. Preview и XLSX каждый используют собственный согласованный снимок; fingerprint обнаруживает изменение между ними.

Ограничения одного файла: 50 000 строк исходной выборки, 50 МиБ исходных записей, 2 млн ячеек и лимит Excel 1 048 576 строк; готовый XLSX — не более 10 МиБ, как штатная загрузка. При превышении возвращается 413 с предложением уточнить фильтры. Файл не обрезается. Пустой результат возвращается в preview, скачивание пустого XLSX запрещено.

Ответ XLSX: проверенный MIME, UTF-8 `Content-Disposition`, `Cache-Control: private, no-store`, `nosniff`. Временные файлы и публичные URL не создаются. События `MASTER_ARRAY_EXPORT` сохраняются в существующий журнал `operation_history` и структурированные логи: actor, requestId, массив, фильтры, количества, размер и статус; STR-данные и JWT не журналируются. Файл отправляется после успешной записи аудита. Неудачные операции после проверки параметров также журналируются; отказ по роли обрабатывается существующим middleware авторизации.

## Проверки

- `tests/master-array-excel-export.test.js`: чтение настоящего XLSX, 620 строк, типы ячеек, все локусы и панели, маскирование пустых колонок, формулы, ЧС/Генетические экспертизы, обратный парсинг штатными `FileValidationService` и `ExcelService`, исторические проблемы и read-only дешифрование.
- `tests/master-array-export.integration.test.js`: реальные PostgreSQL/authenticate, обе административные роли, отказы другим ролям и чужому scope, keyset свыше 500 строк, фильтры, смена fingerprint, подтверждение частичной выгрузки, 50 001 запись без обрезки, журнал успешных/неудачных операций, отказ скачивания при недоступном аудите, неактивные источники и хеш исходных записей до/после.

Интеграционный тест запускается **только** в отдельной БД с именем `dna_master_export_test…`:

```bash
MASTER_EXPORT_TEST_DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/dna_master_export_test \
  node --test tests/master-array-export.integration.test.js
```

Новые миграции не требуются. Проверочные генотипы синтетические; повторная загрузка в рабочую БД не выполняется.
