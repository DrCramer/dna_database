# Проверка установки из GitHub

Проверка выполнена 6 октября 2026 года. Код установки: [`7156985`](https://github.com/DrCramer/dna_database/commit/71569850c3fd98869bd211c86da8d10bba789116).

## Что было воспроизведено

Исходная версия `aa4796c` была заново клонирована из GitHub и установлена через
`./scripts/install.sh` с пустыми каталогами данных. Docker показывал `healthy`,
но были реальные ошибки:

- Инициализация анализа вставляла `system_parameters.parameter_key`, отсутствующий
  в canonical schema. Тип `number` также не соответствовал её CHECK constraint.
- Bootstrap создавал отделения без мастер-массивов: проверка сохранности данных
  возвращала `failed`, а `/health` — `degraded`.
- Права bind mounts зависели от совпадения UID установщика и пользователя `node`.
  При другом владельце каталогов могли быть недоступны логи, экспорт и ключ.
- Самопроверка rollback записывала ожидаемый откат как ошибку приложения.

## Исправления

- Параметры используют существующие колонки и типы `probability`, `threshold`,
  `coefficient`. Параллельная инициализация безопасна; сохранённые значения не
  перезаписываются.
- В `schema.sql` восстановлен триггер создания мастер-массива нового отделения.
  Миграция **030** ремонтирует прежние отсутствующие связи и переиспользует
  существующий активный массив. Профили и существующие массивы не удаляются.
- При ремонте существующей БД установщик сначала создаёт SQL-дамп. Схема и
  справочник новой БД загружаются одной транзакцией.
- `prepare-runtime.sh` проверяет доступ из web и предоставляет группе `node`
  доступ к каталогам, сохраняя владельца на хосте. Web работает от `node`.
- `.env` остаётся `600`, постоянный ключ — `640` с группой `node`. Недоступный или
  повреждённый ключ в production приводит к остановке, без временной замены.
- Защита от генерации новых паролей учитывает недоступный каталог `runtime/`,
  а не только наличие видимого `PG_VERSION`.
- Установщик ждёт полного `/health=healthy`. Ожидаемый rollback самопроверки не
  скрывает реальные ошибки транзакций и не создаёт ложную запись ERROR.

Проверенная среда: Linux amd64, Docker Engine 29.8.0, Docker Compose CLI, Node 20,
PostgreSQL 15 и Redis 7 из образов проекта. Установки от root и UID 10001 запускались
через отдельный Docker CLI с Compose v2; итоговый клон — через установленный Compose.
Состояние другого удалённого сервера зависит также от его Docker, свободных портов,
прав и ресурсов; сам этот сервер в проверке не использовался.

## Автоматические проверки

Полный backend-прогон с тремя отдельными синтетическими БД: **73 теста прошли,
ошибок и пропусков 0**. Добавлены проверки параллельной инициализации параметров,
создания мастер-массива, rollback, повреждённого/отсутствующего ключа и расшифровки
в новом процессе.

```bash
INSTALL_TEST_DATABASE_URL=postgres://.../dna_install_test_... \
IMPORT_TEST_DATABASE_URL=postgres://.../dna_import_test_... \
PROFILE_ACCESS_TEST_DATABASE_URL=postgres://.../dna_profile_access_test_... \
  npm test
```

Docker-сборка выполняет UI-проверку, тесты и production webpack build. В самой
сборке без внешних тестовых БД: **31 тест прошёл**, **3 интеграционных набора
пропущены**; они отдельно проверены в полном прогоне выше. Сборка успешна;
остаются два прежних предупреждения webpack о размере bundle.

Тестовые контейнеры и сети после проверки удалены без удаления bind mounts.
Тестовые БД, настройки, ключи, дампы и диагностические файлы остаются локальными
в `runtime/install-audit-20261006/` и не публикуются.

## Команды на сервере

Новая установка:

```bash
git clone https://github.com/DrCramer/dna_database.git
cd dna_database
./scripts/install.sh
```

Исправление уже созданной новой установки с перечисленными ошибками:

```bash
cd /path/to/dna_database
git pull --ff-only origin main
./scripts/install.sh
docker compose ps
```

Существующие `.env`, `config/encryption.key` и `runtime/` сохраняйте. Пароль
администратора берётся из `.env`; для доступа из сети настройте IP и URL по README.
Для старой БД до миграций 027–029 сначала выполните инструкции соответствующего
релиза. Миграция 030 не заменяет миграции импорта.
