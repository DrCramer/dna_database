# Конвертер старых Excel-файлов генотипов

Конвертер доступен авторизованным пользователям активного отделения **Генетические экспертизы**: меню «Конвертер Excel» (у администратора также «Настройки → Конвертер Excel») или кнопка на странице загрузки. В ЧС этот маршрут и API конвертера недоступны.

## Работа с файлами

1. Выберите несколько `.xlsx` или `.xls`, либо перетащите их на страницу. Нажмите «Проверить и объединить».
2. Проверьте источники: имя файла, лист, строку заголовков, колонку полного номера объекта, локусы и панель.
3. Разрешите записи «Проверить», «Ошибка» и «Конфликт». Экспорт недоступен, пока остаётся хотя бы одна из них. Предупреждения требуют внимания, но допускают экспорт.
4. В таблице профилей можно выбрать колонки источников, всего каталога, заполненные или проблемные. Ячейка локуса источника открывает ручное редактирование с повторной проверкой значения. Полный номер объекта и заголовок остаются видимыми при прокрутке.
5. Скачайте новый Excel либо нажмите «Передать в загрузку профилей». На обычной странице загрузки выберите активную задачу и выполните импорт. Подготовка файла не создаёт профили в БД.

Страница хранит файлы и решения в памяти до перехода или перезагрузки; при смене отделения состояние очищается. Исходные файлы не изменяются. Для сохранения результата скачайте нормализованный Excel. Сервер обрабатывает запрос без постоянного задания и временных файлов.

## Определение структуры

- Приоритетный лист — `SBT_horizont`, регистр и пробелы по краям игнорируются. Иначе единственный содержательный лист выбирается автоматически; несколько листов требуют выбора.
- Заголовок ищется в первых 30 строках: минимум три различных локуса из настоящего `LociTypeDetector`, преимущество у строки с наибольшим количеством локусов и колонкой объекта. При равнозначных строках требуется выбор.
- Приоритеты объекта: «Объект» (включая `Локус/Объект` и переносы), «образца», `N_препарата`, `Sample` / `SampleName` / `Sample Name`, `Smpl`. Если колонки-кандидаты содержат разные значения, нужно выбрать правильную.
- Полный номер сохраняется, включая `x`, скобки и подчёркивания. Только пробелы по краям и повторяющиеся пробелы нормализуются. Слияние не учитывает регистр.
- Служебные `№пп`, `№п/п`, `Smpl`, «Количество локусов НПВ», «Количество исследованных локусов» исключаются. Неизвестные колонки, включая опечатки, требуют явного сопоставления с каталогом или игнорирования. Похожие названия лишь предлагаются.
- Расширенные панели и порядок столбцов поддерживаются по именам, без фиксированного количества локусов.

## Правила значений

| Исходное | Подготовленный результат / действие |
| --- | --- |
| `12 ,13`, `12/13`, `12;13` | `12,13`, журнал изменения |
| `9.3,31.2`, `17.3,18` | Микроаллели сохраняются |
| `11.12` в диплоидном локусе | Решение: разделить `11,12`, оставить микроаллель `11.12,?` или ввести вручную |
| Одна числовая диплоидная аллель `12` | Проверка: подтвердить `12,12`, оставить неизвестную вторую `12,?` или ввести пару |
| AMEL `XY`, `XX`, `YY`, `ХХ` | `X,Y`, `X,X`, `Y,Y`; одиночные X/Y остаются одиночными |
| Одиночная Y-аллель, включая DYS392/SRY/Yindel и зарегистрированные Y-InDel | Сохраняется без дублирования; для Y-InDel допустимы `1` и `2` |
| Пусто, `-`, `–`, `—` | Пустой результат, исходное обозначение в журнале |
| `*`, `**`, `?`, `F` | Специальные токены, `**` канонизируется в `*` с журналом |
| `OL`, `O.L.`, `OFF LADDER`, `OFFLADDER` | `?`; пары `OL,OL` → `?,?`, `OL,15` → `?,15` |
| `ABC`, `ERROR`, `xxx` | Ошибка; пользователь явно задаёт отсутствие результата, неизвестную аллель или ручное значение |
| Три и более аллелей | Все сохраняются в исходном порядке; предупреждение о возможной смеси |

`rs199815934`, `Rs771783753` и `rs759551978` — зарегистрированные гаплоидные Y-InDel. Если для такого маркера указано несколько значений, все они сохраняются с предупреждением о возможной смеси или аномалии. Они не трактуются как длина STR-повторов, не получают значения INS/DEL и не участвуют в аутосомных частотных моделях.

Для одинакового исходного значения и типа локуса можно применить решение ко всему файлу. Это явное правило пользователя, а не автоматическая догадка. Ручной результат снова проходит нормализацию и валидацию.

## Объединение и панели

Доступна [референсная проверка аллелей](ALLELE_REFERENCE_VALIDATION.md): точные лестницы, известные варианты, локальные источники и реальные `population_data`. Настройки включаются независимо. Выбор лестницы основан на явной связи панели; несколько версий требуют выбора. Предложения показывают кандидатов, уверенность и происхождение, но никогда не заменяют неоднозначный генотип автоматически. `Принять предложение` использует прежние ручные решения, а снимок оснований сохраняется в журнале.

По полному номеру объекта объединяются результаты всех строк и файлов. Идентичные аллели (в том числе с переставленным порядком) объединяются; сохраняется порядок первого выбранного результата и все источники. Полноценный результат дополняет отсутствующий или специальный; частичный результат сохраняется при отсутствии полноценного. Противоречащие результаты остаются конфликтом — пользователь выбирает источник либо вводит итог. Ошибки исходных ячеек требуется разрешить отдельно.

Автоматическое назначение панели допустимо только при единственном точном совпадении **локусов источника** с активной панелью доступного отделения. Для частичных совпадений показаны совпавшие, отсутствующие и дополнительные локусы. При слиянии разных панелей профиль не получает произвольную панель; её можно выбрать в обычном импорте.

Разделены:

- `catalogLoci` — весь поддерживаемый каталог, порядок экспортируемых колонок;
- `sourceLoci` — локусы, реально представленные в источниках конкретного объекта;
- `panelLoci` — состав назначенной панели;
- `populatedLoci` — локусы с непустым результатом.

Добавленные пустые колонки каталога не учитываются при назначении панели, подсчёте исследованных локусов и оценке полноты. Неполные генотипы со специальными или неопределёнными аллелями исключаются из расчёта LR.
Специальные значения не становятся обычными числовыми аллелями в сравнении, Bayesian, поиске дублей и контаминации.

## Экспорт и повторный импорт

Новый `.xlsx` содержит:

1. **Импорт**: первая колонка `Объект`, далее каждый локус актуального `ALL_LOCI` ровно один раз в порядке каталога. Пустые отсутствующие значения остаются пустыми; служебные колонки отсутствуют.
2. **Проверка**: файл, лист, строка, объект, локус, исходное/итоговое значения, статус, причина и решение пользователя. Для слияния перечисляются источники.
3. Скрытый **_DNA_META**: формат `dna-genetic-converter`, версия 1, состав источников, `detectedPanelId`, происхождение и журнал существенных изменений. JSON разбит на части с учётом ограничения размера Excel-ячейки.

Обычный `ExcelService` проверяет версию, структуру, объекты, локусы и соответствие заполненным значениям. Панель повторно проверяется через существующий `GenotypePanel.resolveAssignment` в доступном отделении. Метаданные никогда не задают права, организацию, пользователя или задачу. Существенный журнал сохраняется в `notes.conversion`; неизменённые ячейки не размножаются в журнале.

Без `_DNA_META` файл также импортируется: для полной раскладки каталога набор источника определяется по заполненным колонкам всего файла. Доказать присутствие полностью пустого локуса в старом источнике без метаданных невозможно; для сохранения точного состава источника оставьте скрытый лист.

Импорт использует существующие preview/upload, контроль дубликатов, замену деактивированных профилей, проверки задачи, отделения и разрешений `can_upload_with_task` / `can_upload_without_task`. Передача из конвертера лишь подставляет файл в обычный загрузчик.

## API

`POST /api/genetic-excel-converter/preview` и `POST /api/genetic-excel-converter/export`:

- `Authorization: Bearer <accessToken>`;
- `X-Active-Department-Id: <UUID доступного генетического отделения>`;
- multipart: повторяющееся поле `files`, поле `options` с JSON;
- preview возвращает `files`, `profiles`, `issues`, `conflicts`, `summary`, `canImport`;
- export повторно вычисляет результат из оригинальных файлов и решений, возвращает Excel; при нерешённых ошибках — HTTP 409. Переданное клиентом `canImport` не используется.

`options`: `files[fileId]` (sheetName/headerRow/objectColumn/columns/panelId), `cells[cellId]` (action/value), `rules[]` (fileId/code/rawValue/locusType/decision), `conflicts[mergeId]` (sourceId либо action:manual/value), `objects[cellId]`, `rows[rowId].ignore`. Идентификаторы выдаются сервером; при каждом запросе нужно передавать те же файлы в том же порядке.

Ответы приватные (`Cache-Control: private, no-store`). Генотипы, буферы Excel и тела загрузок не выводятся в отладочные логи импорта.

## Ограничения и проверка

До 100 файлов, 10 МиБ на файл, 50 МиБ всего, 20 000 строк / 512 колонок на лист и 50 000 исходных строк на запрос. Настройки до 2 МиБ; журнал метаданных до 16 МиБ и до 1 МиБ на объект. Большие исследования разделяйте. `.xls` поддерживается в обычном контейнере Excel 97–2003; макросы не исполняются. Формулы без сохранённого результата требуют пересчёта источника либо явного значения. Конвертер не вычисляет формулы.

```bash
npm ci --include=dev
npm test
npm run check:ui
npm run build
```

`tests/genetic-converter.test.js` генерирует синтетические книги: пять структур, нормализация, неоднозначности, слияние, конфликты, полный каталог, roundtrip через настоящий ExcelService, поддельные метаданные, регрессии алгоритмов и 2500 объектов. `tests/genetic-import.integration.test.js` проверяет API конвертера и запись результата через штатный импорт в PostgreSQL, включая панель, задачу и отказ по правам. Для интеграционных тестов нужны отдельные БД — см. [инструкцию импорта](GENETIC_IMPORT.md).

## Установка и обновление

Первоначальный конвертер не требовал миграции; референсная проверка добавляет миграцию **031**. Установка: обычный `./scripts/install.sh`. Обновление работающего сервера: `./scripts/update_server.sh` — он создаёт резервную копию, применяет известную добавочную миграцию 031 и пересобирает веб-контейнер. Подробности и ручной порядок: [Референсная проверка](ALLELE_REFERENCE_VALIDATION.md). После обновления откройте генетическое отделение и страницу конвертера.
