# Ревизия интерфейса — 2 октября 2026

## Итоговая архитектура

`frontend/src/index.js` импортирует только `styles/index.css`. Манифест задаёт
порядок: токены и reset → общие элементы → layout → страницы → специфичные
компоненты. Компоненты больше не определяют порядок CSS своими импортами.

`Layout` оборачивает содержимое в `PageShell`. Обычный вариант имеет максимальную
ширину **1400 px**, включая внутренние боковые отступы **24 px**. На планшете
отступы уменьшаются до 20/16 px. При окне 1920 px обычный контент начинается
на x=284 и имеет ширину 1352 px на всех проверенных рабочих маршрутах.

`ProtectedRoute fluid` для `/analysis` выбирает `PageShell` без ограничения
ширины. Рабочая область анализа занимает 1920 px при окне 1920 px. Внутренние
отступы аналитических панелей и плотные генетические таблицы сохранены.

- У Header один источник — `styles/layout/header.css`. Оба варианта меню
  используют высоту навигационных кнопок 42 px. На узком desktop навигация
  занимает второй ряд, на планшете отображаются иконки с доступными подписями.
- Объединены пары `Dashboard.css`/`pages/dashboard.css`,
  `LoginPage.css`/`pages/login.css`, `StaffProfilesPage.css`/`pages/staff-profiles.css`,
  `GenotypeAnalysisPage.css`/`pages/analysis.css`. Специфичные селекторы ограничены
  соответствующей страницей через `:where(...)`.
- CSS пользователей, административного дашборда и поиска перенесён в `styles/pages/`.
- Внутренний Header байесовского модуля переименован в `bayesian-app-header`;
  его стили больше не меняют основную навигацию.
- Локальные определения `.btn`, `.btn-primary`, `.btn-secondary`, общих полей,
  `.page-header` и шаблона модальных окон удалены. Для состояния и расположения
  остались классы соответствующей страницы.
- Alerts определяются только в `alerts.css`, toast-уведомления — в
  `notifications.css`. Анимации получили уникальные имена.
- Общие modal/table/card стили больше не зависят от последней открытой страницы.
  Убрано глобальное растягивание всех окон профилей сотрудников через `!important`.
- Поле выбора образца использует общий `input-group`: внешняя высота 42 px,
  единая рамка и focus-состояние. Убрана двойная рамка, увеличивавшая его до 46 px.
  Кнопки закрытия модальных окон не сжимаются рядом с длинными заголовками.
- Вложенная копия `frontend/src/styles/styles/` проверена по импортам и webpack:
  ссылок нет. Удалены все **19 файлов** этого дерева.
- Удалены не подключавшиеся `Analysis/AlgorithmSettings.css` и `DataTable.css`:
  актуальные настройки используют общие примитивы, таблицы — `pages/analysis.css`.
- Вынесен глобальный `<style>` из `App-fixed.js` в манифест. ThemeContext управляет
  только `theme-light`/`theme-dark`, сохраняя остальные классы `body`.

## Размеры и намеренные исключения

| Элемент | Размер |
| --- | --- |
| Обычные кнопки, input/select, навигация | 42 px |
| Компактные кнопки в таблицах и фильтрах | 36 px |
| Крупные действия загрузки, поля и кнопка входа | 48 px |
| Icon-only | 42×42 px; компактный вариант 36×36 px |
| Модальные окна | sm=420, md=680, lg=960, xl=1240 px; full ограничен viewport |

Ширина текстовых кнопок зависит от содержимого. Checkbox/radio, range, цветовые
образцы и textarea имеют собственную геометрию по назначению. Заголовки, панели,
радиусы и отступы используют общие токены. Карточки быстрых действий занимают
равные треки grid, в том числе при разной длине названия.

Исключения:

- `/analysis` полноширинный. При сравнении до/после на 1920 px таблица сохранила
  ширину **1840 px** и **26 колонок**. `ROW_HEIGHT` виртуальных строк остался **40 px**.
- Для действий внутри этих строк есть `btn-analysis-icon` **32×32 px**:
  увеличение кнопок увеличило бы плотные аналитические строки.
- Просмотр всех локусов сотрудника использует `modal-full`; обычные формы
  сотрудников и остальных страниц не растягиваются глобальным override.
- Hero поиска и приветственный блок Dashboard сохраняют свою композицию;
  размеры внешнего контейнера, цвета и элементы управления общие.
- `!important` остался только для режима reduced motion и аналитических
  цветов/ширин колонок. Подсветка локусов должна перекрывать индивидуальные
  цвета ячеек, выбранные пользователем.

## Существующие ограничения

- В `App-fixed.js` маршруты `/profiles` и `/expert-groups` по-прежнему используют
  legacy-экраны с заглушками. Эта UI-ревизия сохранила маршрутизацию и функции;
  подключение полноценных менеджеров требует отдельной функциональной задачи.
- Авторизация дополнительно проверяет сессии в памяти процесса. После
  перезапуска контейнера старые сессии требуют повторного входа, даже если JWT
  ещё не истёк. Подтверждено на развёрнутом приложении; механизм авторизации
  в рамках UI-задачи не изменялся.
- Старые альтернативные React-компоненты (`App-simple`, некоторые менеджеры)
  остаются в исходниках. Их стили изолированы или используют общую систему;
  они не создают вторую подключённую дизайн-систему.
- Не проверялось создание/удаление реальных объектов и выполнение ДНК-алгоритмов:
  проверялись интерфейс, формы и чтение данных; API, схема БД и алгоритмы не менялись.
