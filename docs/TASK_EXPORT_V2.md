# Выгрузка задачи из main в DNA_IMPORT_V2

`scripts/export-task-v2.js` — **один автономный файл** для запуска на старом
сервере с `main`. Обновлять приложение, применять миграцию 037 или пересобирать
контейнер ради выгрузки не требуется. Используются зависимости старого приложения
`pg`, `xlsx`, `dotenv`; новых пакетов нет. Запускайте из корня проекта или `/app`
web-контейнера, чтобы найти установленные зависимости и настройки.

## Что переносится

- Все записи `dna_profiles`, у которых совпали **task_id и user_id** указанного
  сотрудника. Прямое назначение и групповая задача поддерживаются; чужие владельцы
  не включаются. Организация пользователя и отделение задачи проверяются.
- Номера объектов, год, комментарий, исходные аллели. `F`, `*`, `**`, `?`,
  микроварианты, смеси, одиночные значения и повторы сохраняются без нормализации.
  Для старых структур `allele1/allele2` сохраняются значения и кратность пары.
- Прежние сведения о профиле, примечания, источник файла, panel_id, UUID,
  активность и сведения о выбранной задаче — в «Происхождение JSON».
  Это архив происхождения, он не назначает нового владельца или статус записи.
  Если полное происхождение превышает 32 767 символов, в XLSX остаются основные
  сведения и ссылка с SHA-256 на полную исходную запись в `source-records.jsonl`.
  Полная запись не обрезается. JSONL нужно хранить вместе с XLSX: архивные
  метаданные из него автоматически в новую БД не импортируются.
- У ЧС присвоенный номер берётся из старого `sample_name`, согласно формату main.
  Привоз сохраняется как прежняя служебная колонка, а не подставляется вместо
  номера объекта.

**Не переносятся как действующие сущности:** задача, история её статусов,
результаты поиска, публикации, вложенные исходные файлы и настройки алгоритмов.
В новой версии появятся новые рабочие UUID. Полный резервный комплект старой
установки нужен отдельно: дамп БД, исходный ключ и файловое хранилище.

## Запуск на старом Docker-сервере

1. Сделайте резервную копию старой установки и сохраните её до проверки переноса.
   На время выгрузки и последующей сверки сотруднику следует закончить правки
   задачи: скрипт выгружает согласованный снимок на момент начала, последующие
   изменения в него не попадут.
2. Скопируйте **только** `scripts/export-task-v2.js` из актуальной версии на сервер
   в папку старого проекта, например как `export-task-v2.js`. Не переключайте
   ветку работающего проекта ради получения файла. Относительные пути далее
   указаны от папки старого проекта.
3. Скопируйте файл в уже работающий web-контейнер:

```bash
docker compose -f docker-compose.yml cp ./export-task-v2.js web:/tmp/export-task-v2.js
```

4. Пример для задачи `258` и логина `expert`:

```bash
docker compose -f docker-compose.yml exec -T -w /app web \
  node /tmp/export-task-v2.js \
  --task '258' --user 'expert' \
  --out /app/backups/task-258-expert-v2
```

В стандартном Compose проекта результат окажется на хосте в
`runtime/backups/task-258-expert-v2/`. Если mounts вашей установки отличаются,
результат можно извлечь из контейнера в новую локальную папку:

```bash
docker compose -f docker-compose.yml cp web:/app/backups/task-258-expert-v2 ./task-258-expert-v2
```

Пароль БД и ключ передавать в командной строке не нужно: скрипт читает
`DATABASE_URL` и существующий `ENCRYPTION_KEY_PATH` контейнера. Если указанный
файл ключа отсутствует, поддерживается существующий `ENCRYPTION_KEY` в hex.
Скрипт не генерирует ключи и не загружает сервер приложения/фоновые службы.
При ошибке расшифровки выгрузка целиком прерывается, подмены открытым полем нет.

Если зависимости установлены на хосте, допустим запуск из корня старого проекта:

```bash
node ./export-task-v2.js --task '258' --user 'expert' \
  --out ./runtime/backups/task-258-expert-v2
```

При этом `.env` должен содержать доступный **с хоста** адрес БД. Обычно адрес
`db:5432` предназначен для сети Compose — в этом случае используйте запуск
внутри web-контейнера выше. Скрипт уважает настройки TLS в `DATABASE_URL`,
не отключает проверку сертификата самовольно.

## Выбор задачи и тип объектов

`--task` принимает UUID задачи, её **точное название** или точное значение
`internal_number_start`. Номер объекта или частичное название не используются.
Если нашлось несколько задач, скрипт выведет UUID кандидатов и остановится;
повторите команду с нужным UUID. `--user` — точный логин сотрудника.

У старых генетических экспертиз нельзя надёжно угадать УГ/ГР по отделению.
Без параметра тип останется пустым, его нужно выбрать в черновике новой версии.
Если вы уверены, что **все** выгружаемые генетические объекты одного типа,
добавьте `--type ug` либо `--type gr`. Для старых ЧС тип определяется как `chs`;
параметр, противоречащий сохранённому типу, вызывает остановку. Год не угадывается
по названию задачи/файла или текущей дате.

По умолчанию включены **неактивные** профили: это позволяет сохранить полную
выборку без скрытого отбрасывания. Их прежний статус остаётся в provenance;
новый импорт не восстанавливает деактивацию автоматически. Если нужно перенести
только действующие объекты, явно добавьте `--active-only`.

Профили без `task_id` автоматически к задаче не относятся. Итоговая сводка
покажет их количество у сотрудника и количество записей других владельцев
в выбранной задаче. Нулевой результат — ошибка, а не успешный пустой файл.

## Результат и проверка импорта

Папка назначения должна **отсутствовать**. Существующие результаты не
перезаписываются. Создаются:

- `task-DNA_IMPORT_V2-0001.xlsx`, при необходимости следующие части;
- `source-records.jsonl`: полные расшифрованные исходные записи всех профилей,
  по одной JSON-записи на строку; генотипы и длинные примечания сохраняются целиком;
- `manifest.json`: задача/владелец, число строк, неактивные, отсутствующие год/тип,
  присвоенные номера ЧС, размеры файлов и SHA-256 каждой части, генотипов и JSONL;
  `archivedProvenance` показывает число записей с большим происхождением,
  вынесенным из XLSX. `scriptVersion: 2` обозначает исправленную версию скрипта.

Пакет читается в `REPEATABLE READ READ ONLY`, соединение CLI также запрещает
записи через `default_transaction_read_only`. Профили читаются пачками до 100,
по умолчанию 1000 строк на XLSX-часть (`--part-size 1..1000`). Части больше 8 МиБ
дополнительно разделяются. Нет обрезания по странице интерфейса. Каждый XLSX
повторно читается и сравнивается до записи. Ячейки текстовые, без формул;
Большое происхождение переносится в JSONL автоматически. Если лимит Excel
превышает само поле объекта, комментарий или генотип, операция прерывается
без усечения: сообщение содержит колонку, UUID профиля, размер и адрес ячейки,
но не её содержимое. Уменьшение числа строк в части не решает лимит одной ячейки.
После ошибки созданная этим запуском папка удаляется. После аварийного
завершения процесса неполная папка может остаться: успешный пакет обязательно
имеет `manifest.json`. Перезапуск делайте в новую папку.

Папка создаётся с правами `0700`, файлы — `0600`; они содержат открытые генотипы
и исходные сведения. Передавайте их тем же защищённым способом, что и исходные
файлы. Генотипы, ключ и реквизиты подключения в stdout не печатаются.

В новой версии:

1. Войдите как нужный сотрудник → **Мои генотипы → Загрузить файлы**.
2. Загрузите **все XLSX-части** (не `manifest.json` и не JSONL), сохраните названия колонок
   и свойство `DNA_IMPORT_V2`. Не пересохраняйте файл через сторонние редакторы
   до первичной проверки.
3. Заполните только отсутствующие годы/типы. У ЧС без присвоенного номера
   потребуется исправить исходные сведения; скрипт такой номер не выдумывает.
4. Проверьте замечания, повторы и число включённых объектов по `manifest.json`.
   Неактивные/контрольные образцы могут требовать явного исключения.
5. После импорта сверяйте номера, годы и значения всех локусов. Скрипт проверяет
   файл, но не подтверждает автоматически состояние новой БД после загрузки.
6. Выполните новый поиск; старые результаты не переносятся как актуальные.

Не удаляйте старую установку и резервные копии, пока перенос не проверен.

## Тесты

`node --test tests/task-export-v2.test.js` проверяет CLI, шифрование CBC/GCM,
сохранение аллелей и фактическое чтение актуальным парсером V2, read-only SQL,
разбиение, контрольные суммы, неоднозначность и отказ без частичного результата.
Отдельная регрессия проверяет примечание больше лимита Excel, полный JSONL,
контрольные суммы и чтение компактного происхождения прежним парсером V2.
Интеграционный тест проверяет 4371 профиль и задачу с русским названием;
запускается дополнительно с
`TASK_EXPORT_TEST_DATABASE_URL`: допускается только **отдельная пустая БД**
с именем `dna_task_export_test_*`. Он создаёт минимальную legacy-схему и
синтетические данные. Рабочую БД использовать нельзя.
