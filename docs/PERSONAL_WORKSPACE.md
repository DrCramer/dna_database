# Постоянный личный массив

Использована отдельная таблица `personal_workspaces`, а не скрытая бизнес-задача.
Уникальность `(organization_id, owner_id)` обеспечивается PostgreSQL.
Параллельные первые запросы возвращают один UUID. Рабочие профили остаются в
`dna_profiles`, получают `workspace_id`, категорию, комментарий, ФИО staff,
происхождение и ревизию. Новые записи не требуют department/task/import_number.

«Мои генотипы» открывает собственный массив. Он сохраняется после выхода,
перезапуска и обновления страницы. Переключение справочного отдела не меняет
его состав. В основной таблице есть год, тип, полный номер, ФИО сотрудника,
комментарий и динамический набор локусов. Колонки «Панель» нет; прежние UUID панелей
и их составы сохраняются, справочники доступны внутри организации без слияния имён.

Сортировка доступна по метаданным и локусам. Верхний чекбокс и кнопка выбора
относятся ко всему текущему фильтру, включая строки за пределами страницы.
Правки черновика автоматически сохраняются на сервере с проверкой ревизии.

Выбор профилей служит для полного поиска, удаления, XLSX и публикации.
«Удалить» выполняет soft-delete для аудита: профиль исчезает из действующего набора.
Опубликованный объект и прежние отчёты не удаляются. Повторная загрузка создаёт
новый UUID и не наследует допуск. Старые задачи доступны как архив, без новых
назначений, принятия, закрытия и публикации через approve.

## Права

| Роль | Свой массив | Загрузка при разрешённом праве | Поиск/экспорт своего | Публикация обычных | Публикация сотрудников | Выгрузка для переноса |
| --- | --- | --- | --- | --- | --- | --- |
| admin / system_administrator | читать/изменять | да | да | да | да | да |
| department_head | читать/изменять | да | да | да | нет | нет |
| user_analyst / совместимый analyst | читать/изменять | да | да | нет | нет | нет |
| viewer | чтение | нет | нет | нет | нет | нет |

Никто не получает право менять чужой личный массив подстановкой UUID, включая
администратора. Системный администратор в этих API также работает в организации
своей проверенной учётной записи. Общие опубликованные обычные профили читаются
внутри организации; сотрудники управляются отдельно административными ролями.

Для совместимости право загрузки вычисляется как OR прежних разрешений загрузки
в задачу/без задачи. Не требуется включать `can_upload_without_task` всем экспертам.
В новом меню пользователей показывается одно разрешение загрузки в личный массив;
старые поля API сохраняются. Права анализа/экспорта/изменения существующего массива
проверяются отдельно по роли, отключение загрузки само по себе их не выдаёт и не снимает.

## API

Все запросы требуют Bearer access token действующей сессии. Organization/owner
извлекаются сервером. Заголовок `X-Active-Department-Id` принимается для старых
клиентов и не меняет организацию либо область нового массива.

```http
GET    /api/workspace/config
GET    /api/workspace
GET    /api/workspace/profiles
PATCH  /api/workspace/profiles/:id
POST   /api/workspace/profiles/delete       {"ids":["UUID"]}
POST   /api/workspace/profiles/export       {"ids":["UUID"]}
PATCH  /api/workspace/search-settings       {"parameters":{"minMatches":15}}
POST   /api/workspace/full-search           {"ids":["UUID"],"parameters":{}}
GET    /api/workspace/searches/:id
POST   /api/workspace/searches/:id/duplicates-xlsx
POST   /api/workspace/publication-preview   {"ids":["UUID"]}
POST   /api/workspace/publish               {"ids":["UUID"],"searchRunId":"UUID"}
```

Старые `/api/profiles`, `/search`, `/accessible`, `/:id`, `/master-objects/search`
и `/master-objects/:id` читают собственные рабочие и разрешённые опубликованные
обычные профили. DTO сохраняет полный `internal_number` и добавляет `objectNumber`,
`expertiseType`, `comment`. Чужие личные черновики не раскрываются DNAEXCEL.
Архивные маршруты записи профилей/сотрудников/задач не обходят новый pipeline.

IDENT/TRIO используют ту же математику, частоты и сохранённые снимки. Меняется
организационный выбор источников; прежние расчёты не пересчитываются.
