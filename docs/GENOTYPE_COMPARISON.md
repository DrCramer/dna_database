# Сравнение задач и запись локусов в Excel

## Экспорт

Общий сериализатор формирует одиночную запись вместо одинаковой пары для DYS391, DXS6795 и зарегистрированных RS-маркеров: Rs771783753, rs199815934, rs759551978, Rs2032678. Регистр канонического имени не влияет на правило.

- `10,10` → `10`; одиночное `10` остаётся `10`.
- `10,11`, многокомпонентный профиль `10,10,11`, `10,?` и `?,?` сохраняются.
- Гомозиготы других локусов, например TH01 `8,8`, сохраняют пару.
- Правило применяется к импортному XLSX конвертера, мастер-экспорту и листам «Профили»/«Сравнения» экспорта дубликатов, включая цветной текст.
- Тип ячеек остаётся текстовым. Исходные аллели, их записи в БД и результаты анализа не переписываются.

Мастер-экспорт учитывает это представление при предварительной проверке обратного импорта. Неправильные исходные значения не исправляются автоматически.

## Критерии

**Стандартный поиск** требует совпадения полного известного набора аллелей без учёта порядка. Одиночное значение и его одинаковая пара эквивалентны в обоих направлениях. Одно значение не является точным совпадением с гетерозиготой или смесью. Неизвестная/специальная аллель не создаёт полного совпадения. Минимум совпавших локусов обязателен.

**Поиск дублей v5** применяет одновременно три условия:

```text
totalScore >= minScore
matchPercentage >= minPercentage
comparedLociCount >= minLoci
```

Параметр `minMatches` стандартного поиска не заменяет отдельные настройки v5. Нулевые балл/процент принимаются как явные значения. Сам расчёт весов и баллов v5 сохранён: полное совпадение 1, drop-out 0.6, включение в смесь 0.8, частичное пересечение −0.5, несовпадение −1, с учётом весов локусов.

Число сравненных локусов включает и несовпадения; число совпавших — только положительные статусы match/dropout/contamination. В столбце «Совпавшие локусы» экспортного листа «Сравнения» по-прежнему считаются только полные зелёные совпадения.

**Контаминация** использует выбранную версию алгоритма и минимальное число совпадений. Высокая оценка не обходит этот минимум. Настройка версии передаётся и в поиск по задачам отдела.

Правила применяются одинаково в последовательном расчёте и worker threads. Предобработка точного сравнения выполняется один раз для каждого профиля, чтобы не сортировать аллели заново для каждой пары.

## Доступ к задачам сотрудников

Перед чтением профилей сервер проверяет UUID задачи, доступ к активному отделению/организации через существующий ProfileAccessService и доступ к исходной задаче через существующий AccessPolicyService. Поддерживаются назначение пользователю, участие в группе и действующие административные права, с обязательным ограничением активным отделением.

Для сравнения выбираются другие активные задачи этого отделения со статусом `in_progress`. Завершённые, отменённые, неактивные задачи и неактивные профили исключаются. Каждая выборка профилей дополнительно ограничена отделением и организацией, даже если историческая запись ошибочно связана с чужой задачей. Эти же проверки выполняются при восстановлении профилей результатов через `department-profiles`.

Некорректные параметры дают 400, недоступная задача — 403, отсутствующая или неактивная — 404. Существующие данные и назначения задач при поиске не меняются.
