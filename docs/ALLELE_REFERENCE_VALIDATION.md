# Референсная проверка аллелей

## Подключение через интерфейс

1. Выберите отделение **Генетические экспертизы** и откройте **Настройки → Генетические справочники**.
2. Администратор, системный администратор или руководитель отделения добавляет справочник. Обычный пользователь может просматривать данные и использовать их в конвертере.
3. Укажите тип, набор, производителя, название документа, URL, версию и, если известна, точную дату публикации. Названия наборов свободные: GlobalFiler, GlobalFiler IQC, VeriFiler, PowerPlex и собственные системы поддерживаются без отдельного кода.
4. Загрузите CSV/JSON, подтвердите сверку с источником, нажмите **Проверить данные**, затем **Сохранить проверенную версию**.
5. В карточке источника отметьте соответствующую панель. То же можно сделать в редакторе панелей. Совпадение названия панели с коммерческим набором само по себе ничего не назначает.
6. В конвертере выберите автоматический режим или конкретную лестницу. Если у панели несколько активных лестниц, выберите версию явно, при необходимости отдельно для каждого исходного файла.
7. У спорной ячейки рассмотрите кандидатов, уверенность и источники. **Принять предложение**, **Оставить микроаллель**, ручной ввод и существующие массовые правила используют прежний механизм решений.

## Какие данные поставляются

Подготовлен локальный JSON **PowerPlex Fusion — TMD039 Revised 7/20**: 24 локуса и 367 точных строк аллелей из Table 7, стр. 72 [официального руководства Promega](https://www.promega.com/-/media/files/resources/protocols/technical-manuals/tmd/powerplex-fusion-system-protocol.pdf?rev=55bf6471c78e44549d5e49c15ef5bb6e&sc_lang=en). Это пятицветная система PowerPlex Fusion, не Fusion 6C. Перечень сверялся 08.10.2026; дата документа известна только до месяца, поэтому точная `source_date` не придумана. В JSON хранятся явные строковые значения; развёрнуты только интервалы, прямо перечисленные производителем в таблице. Пропуски D2S1338, D19S433, FGA и микроаллели сохранены.

В меню источников нажмите **Подготовить PowerPlex Fusion TMD039 7/20**, проверьте соответствие вашей лабораторной системе и сохраните через обычную проверку. Этот файл не импортируется в PostgreSQL и не связывается с панелями автоматически. Полный PDF производителя в репозиторий не включён; сохранены числовые справочные данные, ссылка, редакция и номер таблицы.

Для **GlobalFiler / IQC / VeriFiler** реализован ручной импорт точных списков из официальной документации [Thermo Fisher](https://www.thermofisher.com/us/en/home/industrial/forensics/human-identification/forensic-dna-analysis/pcr-amplification-forensic-dna-profiling/globalfiler.html). При исследовании автоматическое чтение найденного PDF GlobalFiler вернуло HTTP 403. Непроверенные лестницы и предполагаемое соответствие IQC не добавлены.

Для [NIST STRBase](https://strbase.nist.gov/) реализован тип `NIST_VARIANTS`, для [YHRD](https://yhrd.org/) — `Y_STR_REFERENCE`. Веб-страницы STRBase требуют исполнения приложения, а доступное извлечение не дало полной проверяемой выгрузки. Эти базы не скопированы и не предзаполнены: загружайте проверенные записи с указанием версии и условий использования. Фрагменты архивных справок не выдаются за полную актуальную базу. Локальные проверенные записи импортируются как `OBSERVED_REFERENCE`.

Популяционные данные читаются из существующей `population_data` через `PopulationManager.loadObservedRecords()`. Новая миграция не добавляет частоты и не заменяет уже подключённые базы. В новой установке таблицы справочников пусты до явного импорта.

## Формат импорта

Для CSV обязательны `Locus,Allele`; необязательны `Kit,Classification,Source,Version`. Если необязательные сведения присутствуют, они должны совпадать с настройками набора и источника. Поля в кавычках, экранированные кавычки, BOM и переносы строк поддерживаются. Аллели не преобразуются в числа.

```csv
Kit,Locus,Allele,Classification
ExampleKit,TH01,9.3,IN_LADDER
ExampleKit,D5S818,11,IN_LADDER
ExampleKit,D5S818,12,IN_LADDER
```

Это **вымышленный пример структуры**, не лестница коммерческого набора. В настройках укажите `ExampleKit`.

JSON: объект с `loci`, объект с `values` или массив записей. Например:

```json
{"kit":"ExampleKit","loci":{"TH01":["9.3"],"D5S818":["11","12"]}}
```

Для записи поддерживаются `locus`, строковая `allele`, `classification` и `metadata`. Типы классификации: `IN_LADDER` только для лестницы; `KNOWN_VARIANT`, `OFF_LADDER`, `TRIALLELIC_VARIANT`, `OBSERVED` для вспомогательных справочников. Спецтокены и диапазоны в импортируемых аллелях запрещены; JSON-число `9.3` отвергается, нужна строка `"9.3"`. Неизвестные локусы и дубликаты отвергаются. Лимиты: 8 МиБ и 20 000 записей на версию.

## Логика оценки

`AlleleNormalizer` формирует синтаксические кандидаты; `AlleleReferenceService` независимо оценивает их. Для `11.12`: одна аллель `11.12` либо пара `11,12`. Для `9.3`, `31.2`, `17.3`, `14.2` кандидат разделения не создаётся.

| Основание | Значение |
|---|---|
| `IN_KIT_LADDER` | Точное присутствие в выбранной лестнице |
| `KNOWN_VARIANT` / `KNOWN_OFF_LADDER_VARIANT` | Подтверждённый вариант; возможное отсутствие в конкретной лестнице |
| `OBSERVED_IN_LOCAL_REFERENCE` | Подтверждённая локальная запись |
| `OBSERVED_IN_POPULATION` | Реальная положительная частота в выбранной базе |
| `NOT_OBSERVED_IN_DATASET` | Нет положительного наблюдения; отсутствующая частота — `null`, нулевая запись сохраняется как `0` |
| `NOT_REPORTED_IN_REFERENCE` | В покрытом локусе запись не найдена; это не доказательство невозможности |
| `NO_REFERENCE_DATA` | Нет подходящего источника или покрытия локуса |
| `CONFLICTING_REFERENCE_EVIDENCE` | Источники поддерживают разные интерпретации |

При единственной интерпретации, полностью поддержанной выбранной лестницей, предлагается `HIGH`. Несколько независимых вспомогательных источников без лестницы дают `MEDIUM`; одиночный вспомогательный источник и противоречия — `LOW`; отсутствие данных — `UNKNOWN`. Уровень обозначает прозрачное правило приоритета, **не откалиброванную вероятность**. Проценты не выводятся.

Частоты сами по себе не выбирают исправление. Частая аллель не доказывает правильность записи. Резервные частоты, частоты соседних аллелей и минимальные значения LR не поступают в референсную оценку. Если альтернативная интерпретация наблюдалась в популяции, уверенность предложения лестницы снижается. Если обе интерпретации подтверждены справочниками, предложение не выбирается.

`VALID_KNOWN_ALLELE` подтверждает существование значения. Проверка одиночной аллели диплоидного локуса продолжает требовать решения `12,12` или `12,?`. Предупреждения о более чем двух аллелях и нескольких аллелях Y не снимаются. `OL,15` сохраняется как `?,15`; анализируется только известная часть. `OL` не восстанавливается. Для Y-STR используются сведения о значениях; независимые аутосомные частоты и вероятности гаплотипов не рассчитываются. `SRY`, `Yindel`, AMEL сохраняют правила своего типа.

## Хранение и воспроизводимость

Миграция **031** добавляет `allele_reference_sets`, `allele_reference_values`, `genotype_panel_references`. Все наборы и связи ограничены организацией/активным отделением. Составные внешние ключи запрещают связь с чужой панелью или источником. У значений уникальный индекс `(reference_set_id,locus_name,allele)`.

Содержимое версии через API неизменно. Обновление — создание новой версии с `previousSetId`; старую можно деактивировать. Активность перечитывается при каждом запросе. Содержимое кэшируется по UUID + SHA-256 версии, не более 32 наборов; деактивация сбрасывает кэш. Популяционные строки перечитываются пакетно, поэтому изменения частот не требуют ожидания TTL. На конвертацию выполняется одна загрузка строк частот по поддерживаемым локусам, а не запрос на каждую аллель; справочные значения загружаются одним запросом для отсутствующих в кэше версий. Индексы локусов/аллелей строятся в памяти.

Аудит хранит оригинал, кандидатов, уровень доказательности, UUID и версию набора, хэш содержимого, тип/ссылку источника, реальные частоты, снимок версии популяционных строк, уверенность, решение оператора и применённое значение. Снимок остаётся в `_DNA_META` и обычном импорте (`notes.conversion.audit`) после изменения справочника. Открытый лист «Проверка» содержит дополнительные колонки предложения и оснований; длинная видимая ячейка ограничена Excel, полный журнал сохраняется в скрытых метаданных. Общие лимиты журнала 16 МиБ / 1 МиБ на объект действуют и здесь.

Конвертация не пишет профили или reference sets и не обращается в интернет. Предыдущие профили, формулы LR, существующий импорт ЧС и права загрузки сохранены. Старый `PopulationFrequencies` адаптирован к `population_data` с сохранением интерфейса и расчётных резервных оценок; отсутствующие в схеме таблицы больше не запрашиваются. Его расчётные методы не используются конвертером.

## API

Запросы требуют Bearer-токен и `X-Active-Department-Id`.

| Путь | Операция |
|---|---|
| `GET /api/allele-references?includeInactive=true` | Список и происхождение версий |
| `GET /api/allele-references/:id?locus=TH01` | Значения конкретной версии / локуса |
| `POST /api/allele-references/validate` | Проверка формата без записи |
| `POST /api/allele-references` | Создание неизменяемой версии |
| `PATCH /api/allele-references/:id` | Только `{ "isActive": false/true }` |
| `GET /api/allele-references/:id/compare?other=UUID` | Добавленные/удалённые/изменённые значения |
| `GET /api/allele-references/populations` | Существующие частотные базы |
| `GET /api/allele-references/templates/promega-fusion-tmd039-2020` | Проверенный локальный шаблон, без записи |
| `POST/PUT /api/genotype-panels[/:id]` | Дополнительное поле `referenceSetIds` |

Настройки конвертера в прежнем multipart-поле `options`:

```json
{"reference":{"ladder":true,"variants":true,"population":true,"referenceSetId":"auto","populationIds":[]}}
```

`referenceSetId`: `auto`, `none` или UUID доступной активной лестницы. `files[fileId].referenceSetId` переопределяет выбор для конкретного файла. `populationIds: []` использует все доступные базы. В `issues[].reference` находятся `candidates`, `suggestedValue`, `suggestedDecision`, `confidence`, `reason`; `referenceSummary` содержит числа неоднозначностей и предложений. `options.cells`, `options.rules` и `options.conflicts` остаются прежним механизмом подтверждения.

## Установка, обновление и откат

Новая установка: обычный `./scripts/install.sh`; актуальные `schema.sql` и `init.sql` содержат DDL справочников. Установщик проверяет наличие новых таблиц в существующей базе и применяет 031 после дампа. Скрипт обновления распознаёт добавление 031 и применяет её после резервной копии, затем собирает веб-контейнер. Также он проверяет наличие таблиц, если код уже получен отдельным `git pull`. Если прежний скрипт остановился после получения этого релиза из-за изменения схемы, повторите `./scripts/update_server.sh`: обновлённый скрипт создаст дамп и установит недостающие таблицы. Неизвестные изменения схемы по-прежнему требуют разбора миграций.

Для ручного обновления после `git pull --ff-only`:

```bash
mkdir -p runtime/backups
docker compose exec -T db pg_dump -U dna_user -d dna_analysis > runtime/backups/before_031.sql
test -s runtime/backups/before_031.sql
docker compose exec -T db psql -U dna_user -d dna_analysis -v ON_ERROR_STOP=1 < database/migrations/031_allele_references.sql
docker compose build web
docker compose up -d --no-deps web
```

Миграция повторяема, работает в транзакции, не переписывает и не удаляет профили или частоты. Откат: сначала вернуть предыдущий образ приложения и сохранить добавленные справочники, затем при необходимости применить `database/rollbacks/031_allele_references.sql`. Откат удаляет только новые reference tables/связи; старый аудит профилей не удаляется.

Дополнительная переменная `ALLELE_REFERENCE_TEST_DATABASE_URL` должна указывать на БД с именем `dna_reference_test...`; рабочую PostgreSQL не используйте.

Обязательные команды: `npm ci --include=dev`, `npm test`, `npm run check:ui`, `npm run build`; Dockerfile выполняет проверки при сборке.

Проверка 08.10.2026: полный набор из **127 тестов** прошёл с четырьмя отдельными PostgreSQL-базами, без пропусков. Заключительный запуск двух файлов референсных тестов — **21 проверка**, включая отказ с HTTP 400 для некорректных настроек. Проверка CSS и production-сборка прошли; Webpack сохранил предупреждения о размере существующего bundle. В отдельном Docker-контейнере браузером проверены импорт 367 записей PowerPlex, просмотр микроаллеля, привязка панели, предложение `11,12`, запрет экспорта до подтверждения, подтверждение и скачивание XLSX. Пользователь-аналитик видит справочники, но не может изменять их или связи. На ширинах 1366, 1440 и 1920 пикселей проверенные страницы не создают горизонтального переполнения.
