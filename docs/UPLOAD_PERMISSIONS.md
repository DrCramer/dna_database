# Права загрузки профилей

## Настройка

Откройте **Пользователи**, создание или редактирование пользователя, раздел
**Права загрузки ДНК-профилей**. Доступны два независимых переключателя:

- **Разрешить загрузку в активную задачу** — включён по умолчанию.
- **Разрешить загрузку без задачи** — выключен по умолчанию для всех ролей.

Выключение обоих переключателей полностью запрещает загрузку. Настройками
управляет администратор; руководитель видит их без возможности изменения.
Существующие права роли и доступ к отделениям также проверяются.

Для обычной загрузки начните задачу, выберите её на главной странице и перейдите
к загрузке. Задача должна иметь статус **«В работе»**, относиться к активному
отделению и быть доступна пользователю: назначена ему/его действующей экспертной
группе либо доступна руководителю или администратору. Завершённые, утверждённые,
отменённые, ещё не начатые и неактивные задачи для загрузки запрещены.

Без задачи выбор файла и загрузка блокируются с объяснением и переходом к выбору
задачи. При явно выданном исключении интерфейс сообщает, что профили будут
сохранены без привязки. Выбор другой задачи или отделения очищает прежний файл
и предпросмотр. Права обновляются при открытии страницы, возврате фокуса и
начале загрузки. Backend читает актуальные настройки из БД при каждом запросе.

## API

Поля пользователя: `can_upload_with_task` и `can_upload_without_task`, только
boolean. Они возвращаются при входе, в `/api/auth/me` и списке пользователей.
Настройки сохраняются через `PUT /api/users/:id` и создание пользователя через
`POST /api/auth/register-with-department`. Частичное обновление прав не меняет
отделения и не требует окончания существующих сессий. Изменения прав записываются
в историю с прежними и новыми значениями.

Preview, upload и bulk-upload используют одну проверку. `taskId` передаётся
в multipart вместе с файлом; `X-Active-Department-Id` выбирает доступное отделение.
Случайный UUID, чужая задача, другое отделение или неподходящий статус не позволяют
обойти запрет. Параметры `skipValidation`, `validationOnly`, `allowDuplicates`
и подставленные права в теле загрузки также не обходят проверку.

Основные коды ошибок:

| Код | HTTP | Причина |
|---|---:|---|
| `TASK_REQUIRED` | 403 | Без задачи загружать запрещено |
| `TASK_UPLOAD_FORBIDDEN` | 403 | Загрузка в задачу запрещена настройкой |
| `INVALID_TASK_ID` | 400 | Некорректный UUID |
| `TASK_NOT_FOUND` | 404 | Задача отсутствует или неактивна |
| `TASK_DEPARTMENT_MISMATCH` | 403 | Другое отделение |
| `TASK_ACCESS_DENIED` | 403 | Нет доступа к задаче |
| `TASK_NOT_IN_PROGRESS` | 409 | Задача не находится в работе |

## Обновление

Новая установка использует обновлённый `database/schema.sql`. Для существующей
БД перед запуском нового web-образа примените миграцию 028. Если ещё не применена
027, сначала выполните [обновление формата импорта](GENETIC_IMPORT.md).

```bash
cd /путь/к/dna_database
set -e
umask 077
mkdir -p runtime/backups
docker compose exec -T db pg_dump -U dna_user -d dna_analysis \
  > "runtime/backups/before_upload_permissions_$(date -u +%Y%m%d_%H%M%S).sql"
docker compose build web
docker compose stop web
docker compose exec -T db psql -U dna_user -d dna_analysis -v ON_ERROR_STOP=1 \
  < database/migrations/028_profile_upload_permissions.sql
docker compose up -d --no-deps web
docker compose ps
```

Миграция повторяется безопасно и сохраняет уже выданные исключения. Данные
профилей и их существующая привязка к задачам не переписываются. Для ранее
загруженных без задачи профилей требуется определить конкретную задачу для
привязки; запрет новых загрузок не назначает старые профили автоматически.
После перезапуска web требуется повторный вход.

## Проверки

39 проверок прошли с отдельной PostgreSQL БД, включая все сочетания прав,
сохранение/отзыв настроек, создание пользователя, активное дополнительное
отделение, принадлежность профиля задаче, членство в группе, доступы и статусы,
защиту preview/upload/bulk от обхода и прежние тесты импорта genetic/ЧС.
Проверка UI и production build выполняются также при Docker build.

На работающем контейнере проверены блокировка выбора файла без задачи,
обновление прав из `/api/auth/me`, значения по умолчанию при создании пользователя
и отправка двух boolean при редактировании. При изменении только прав форма
не пересохраняет отделения пользователя. На ширине 375 px переключатели доступны
без горизонтальной прокрутки. API возвращает `403 TASK_REQUIRED` для предпросмотра
без задачи и `200` для доступной задачи в работе; просмотр её профилей также
доступен после привязки ранее загруженных данных.
