# Работа с dna_database

## Документация

Используй установленный Context7 для документации, примеров, настройки и отладки
сторонних библиотек. Сначала разреши library ID, учитывай версию из lock-файла.
Запросы должны быть общими: не передавай секреты, персональные данные, ДНК-профили
или закрытый код. Если Context7 недоступен, сообщи об этом и используй официальную
документацию библиотеки.

## Специализированные агенты

В `.codex/agents/` определены четыре роли. При запросе делегирования выбирай роли
по задаче; запускать все четыре для каждого изменения не требуется:

- `dna_qa`: воспроизведение ошибок, проверки UI через Playwright MCP, регрессии.
- `dna_security`: права API, задачи, отделения, импорт, экспорт и секреты.
- `dna_algorithms`: STR-аллели, конвертер, сравнение, дубликаты и XLSX.
- `dna_devops`: Docker, чистая установка, обновление, сохранность томов.

Делегируй конкретный объём работы и файлы. По умолчанию проверяющие возвращают
выводы; изменения поручай явно. Модель и права наследуются от основной сессии.

## Проверки и данные

- Команды проверок: `npm run check:ui`, `npm run check:imports`, `npm test`,
  `npm run build`. Выбирай проверки по изменению; перед выпуском учитывай все
  обязательные этапы Dockerfile. Отдельно указывай пропущенные проверки и TODO.
- Интеграционные тесты запускай на отдельной тестовой БД с синтетическими данными.
  Например, `CRITERIA_TEST_DATABASE_URL` требует имя `dna_criteria_test...`,
  `MASTER_EXPORT_TEST_DATABASE_URL` — `dna_master_export_test...`.
  Проверяй ограничения конкретного теста перед запуском.
- Не используй рабочую БД для фикстур и не выводи `.env`, токены, хеши паролей,
  ключ шифрования или реальные генотипы в отчёты и сторонние MCP.
- Сохраняй `.env`, `config/encryption.key`, `runtime/` и `logs/` при обновлениях.
  Порт хоста 3000 занят; у приложения по умолчанию 3001. Для проверок выбирай
  свободные порты и изолированные тома, учитывая фиксированные `container_name`.
- Для Sentry проверяй, что подключение авторизовано и выбран нужный проект.
  Установка MCP сама по себе не включает отправку ошибок из приложения.
  Изменения в Sentry и отправку данных выполняй в пределах поручения пользователя.

## Предметные ограничения

- Изменения отображения и экспорта не должны переписывать исходные генотипы.
- Сохраняй микроварианты, специальные значения, смеси и исходную одиночную запись
  аллелей согласно формату. Типы локусов проверяй по `src/utils/lociTypeDetector.js`.
- Сравнение, счётчики совпадений и экспорт проверяй согласованно; права на исходную
  задачу и область отделения должны действовать во всех путях API и воркерах.

Инструкции по подключению инструментов и примеры вызова ролей находятся в README.
